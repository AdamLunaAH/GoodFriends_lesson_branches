To create the AppWebApi, all Azure resources and publish

1. Create all resources in Azure.
   Resource group, KeyVault, Application tenant to read KV, SQL databas
   In UserSecrets you see the full path to your azure resource settings under tag ApplicationSecrets:AzureSettings   
   
   You can use the scripts by opening a terminal in _scripts/azure and run
   You can use the scripts by opening a terminal in _scripts/azure and run
   macOS
      ./az-create-all.sh ./az-resource-params/data-access /Users/Martin/Development/goldenProjects/GoodFriends_lesson_branches/Configuration/Configuration.csproj

   Windows
      ./az-create-all.ps1 ./az-resource-params/data-access C:\Users\Martin\Development\goldenProjects\GoodFriends_lesson_branches\Configuration\Configuration.csproj

   Log in to your Azure account and confirm the resources


2. All role based connection strings are generated by Azure and stored by the scripts in the file
2. Place the Azure settings location, full path to AzureSettings tag in appsettings.json 
   Examples
   macOS
      "AzureSettings": "/Users/Martin/Development/goldenProjects/GoodFriends_lesson_branches/_scripts/azure/az-resource-params/data-access"
   Windows
      "AzureSettings": "C:\\Users\\Martin\\Development\\goldenProjects\\GoodFriends_lesson_branches\\_scripts\\azure\\az-resource-params\\data-access\\az-access"


3. All role based connection strings are generated by Azure and stored by the scripts in the file
   
   macOS
   /Users/Martin/Development/goldenProjects/GoodFriends_lesson_branches/_scripts/azure/az-resource-params/data-access/az-secrets/az-sql-con-string.json

   Windows
   C:\Users\Martin\Development\goldenProjects\GoodFriends_lesson_branches\_scripts\azure\az-resource-params\data-access\az-secrets\az-sql-con-string.json

   Update the Azure sql connection strings in User secrets by replacing the user secrets block with the block in the generated file
   "sql-friends.sqlserver.azure.root" : "..."
   "sql-friends.sqlserver.azure.dbo" : "..."
   "sql-friends.sqlserver.azure.usr" : "..."
   "sql-friends.sqlserver.azure.supusr"  : "..."
   "sql-friends.sqlserver.azure.gstusr"  : "..."


4. Update Azure KeyVault with the content of your user secrets
   With Terminal in folder _scripts 
   
   macOs 
   ./az-kv-update.sh
   
   Windows 
   ./az-kv-update.ps1

5. Create the database. With Terminal in folder _scripts 
   
   macOs
   ./database-rebuild-all.sh sqlserver azure
   
   Windows
   ./database-rebuild-all.ps1 sqlserver azure

   Ensure no errors from build, migration or database update


5. From Azure Data Studio you can now connect to the database
   Use connection string from user secrets:
   connection string corresponding to Tag
   "sql-friends.<db_type>.azure.root"

6. Use Azure Data Studio to execute SQL script DbContext/SqlScripts/<db_type>/azure/initDatabase.sql

7. Run AppWebApi with or without debugger

   Without debugger:   
   Open a Terminal in folder AppWebApi run: 
   dotnet run -lp https 
   open url: https://localhost:7066/swagger

   Verify your can execute endpoint Admin/Environment and Guest/Info

8. Use endpoint Admin/SeedUsers to seed users into the database

9. Use endpoint Guest/LoginUser to login as dbo1
{
  "userNameOrEmail": "dbo1",
  "password": "dbo1"
}

10. Authorize using Swagger Authorize butto and paste in the encryptedToken recieved after login.
    NOTE!!: Copy and paste the encryptedToken WITHIN the quotation, i.e. WITHOUT the first and last quotation mark "

11. Use endpoint Admin/Seed to seed the database, Admin/RemoveSeed to remove the seed
   Verify database seed with endpoint Guest/Info
   As dbo you can now use and play with all endpoints
